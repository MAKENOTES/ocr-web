## 3. 剩余错误的主要构成

错误快照来自当前 `recognition/error_cases.txt`：报告头为 Accuracy 96.964%、CER 0.442%，共 290 张、390 次编辑。两条记录已被整理为三行格式，本次只在内存中还原统计，原文件未修改；290 条 GT 均与当前 val 标注一致。

**它与第 491 轮日志并不完全一致**：491 轮日志对应约 291 张错误、391 次编辑。评估入口当前指向 epoch 491，但错误文件没有权重和数据哈希，不能将该清单严格认定为该 checkpoint 的原始评估。以下用于确定问题方向；候选权重排名以 TensorBoard 为准，最终比较需在固定输入上重评。

| 编辑统计 | 次数 |
|---|---:|
| 字符替换 | 295 |
| 漏字（GT→预测删除） | 61 |
| 多字（GT→预测插入） | 34 |
| 仅涉及 Unicode 标点/符号的编辑 | 168 / 390（43.1%） |
| 只含上述标点/符号编辑的样本 | 126 / 290（43.4%） |

常见模式：`;→：` 22 次、`;→；` 12 次、`；→;` 7 次；下划线漏识 11 次、增识 9 次；句号漏识 8 次。上述既包含模型识别问题，也可能包含标签规范问题，不能把这 126 张全部计为错标或自动归一化消除。

`;` 在真实训练文字中出现 562 次、旧六份合计 958 次；`；` 分别为 126/472 次；下划线为 402/708 次。优先核查它们的视觉定义和训练标签一致性，单靠补字符数量不一定能解决。

按图片文件名关联 09-09 的人工复核分类，当前错误中有：红章类 **73 张 / 125 次编辑**，边缘残字类 **25 张 / 26 次编辑**，历史标注错误与混合错误类 **21 张 / 39 次编辑**。另有 **77 张**没有旧分类。这是历史类别交集，并未重新逐张看图，不能认为这些错误全部由原分类原因造成，也不能把交集减少直接解释成训练改善。

优先复核清单：

1. 21 张曾被标记为标注问题的图片，确认当前标签是否已修正；明确项才改标，并保留版本和前后值。
2. `; / ； / ：`、中英文逗号、句末点、正文下划线与版式下划线。只有业务认定语义等价的字符才建立规范；小数点、金额分隔符和邮箱中的 `_` 不能随意合并或删除。
3. 红章、长英文混排、边缘残字分组，包括 `000644-000029.png` 的 `IlluminaHiseq或NovaSeq平台` 和 `000540-000037.png` 的 OTU 文本。

严格 CER 始终保留。若业务需要额外的归一化评分，将它作为第二指标并明确规则。标注规范确定后必须同时应用于训练与评估标签，历史分数保留原版本，不能只修改验证答案获得更好分数。

## 4. 优先验证几何增强是否制造了缺字监督

`RandomBackgroundGeometry` 在缩放到高度 32 后，对所有训练图应用 ±2° 旋转，使用固定画布和默认最近邻插值，然后以 30% 概率做透视。固定画布不会容纳旋转后越界部分，见 [TorchVision RandomRotation 文档](https://docs.pytorch.org/vision/stable/generated/torchvision.transforms.RandomRotation.html)。

宽 1,000 px 的文字行旋转 2° 时，左右端中心相对原中心线垂直移动约 `500 × sin(2°) = 17.45 px`，已超过画布半高 16 px。真实字符是否被切取决于位置和留白，但该范围有明确的内容丢失风险。当前 val 缩放后 486 张宽度至少 1,000 px、736 张至少 800 px；最长 1,733 px，均未超过训练宽度上限 1,800，因此验证宽度上限不是本次主要差异。

首个消融只设 **rotation degrees=0**，保持透视、颜色、去章、dropout 和数据不变，观察长文本及边缘分组。随后再单测关闭透视。若旋转关闭有效，后续可改为按长宽比限制角度或原图阶段补足画布后变换，并验证字符可见性与有效宽度；不要仅把 2° 改成 1° 就假定所有长行安全。

`RandomErasing(value="random")` 和文档反色也值得后续单独消融；先处理证据更直接的几何变换。模型当前 CNN/RNN dropout 均为 0.1，不是历史记录中的 0.3，暂时保持不变。

## 5. 下一轮的具体实验方案

先固定 keys、预处理版本、训练/验证清单及 hash，保存当前最佳权重 `1789010491best_cer_0.0043_epoch_432.pth` 的独立基线副本。对 432、491、495 用同一固定验证集重评，结果另存文件；权重名只保留四位 CER，小差别必须看完整数值。

训练入口当前没有加载权重或恢复训练状态的逻辑，只保存 `model.state_dict()`。直接重启 `train.py` 会从头训练。微调前需增加显式权重初始化与独立输出目录；历史文件缺 optimizer/scheduler，不能宣称无缝续训。以后同时保存优化器、调度器、epoch、step、随机状态、配置及数据/字典 hash，并记录实际学习率和每组样本数。

以下参数是待验证的实验起点，不是已经验证有效的配置：

| 实验 | 从同一基线开始的唯一主要变化 | 目的 |
|---|---|---|
| A 对照 | 旧六份数据与现有增强 | 测量低学习率继续训练本身的收益 |
| B 旋转消融 | A 的 rotation degrees=0 | 验证固定画布旋转是否影响长行和边缘文字 |
| C 新增数据 | A 加入 confusable/degraded/edge 各 1,000 张 | 测量这批已生成数据的实际收益 |
| D 组合 | 仅组合 B/C 中有效项 | 确认收益组合后仍成立 |

所有实验统一从 epoch 432 初始化，RGB、高度 32、batch 64、AdamW、weight_decay=1e-4、dropout=0.1、clip=2 保持相同；新建优化器。首轮每组 **20,000 optimizer steps**，学习率固定 **3e-5**，每 **2,000 steps** 用同一验证集评估。用相同随机种子和更新步数比较，避免加数据后每个 epoch 预算不同。约相当于旧数据 11.4 轮，只做初筛；表现稳定的候选再延长 20,000–40,000 steps，至少复核另一个 seed。A/B/C 串行即可，不需要同时占满 GPU。

如新增数据在常规比例下收益不足，再比较“真实 50% / 原合成 35% / 红章及专项 15%”的采样起点。比例按样本曝光定义，原合成与专项清单须互斥，保留低频字覆盖；采样时继续满足宽度分桶和动态 padding，不能用固定 batch 同伴替代随机组批。当前桶采样只打乱 batch 顺序，batch 内成员固定，这是第二阶段可单独检查的因素。

验收以固定版本的逐样本结果为准：整体 CER 和全串准确率同时看；分组报告红章、合法红字、标点、姓名、英文数字、长行、边缘文字的样本数、字符数、编辑数和整串错误数。包含正确样本，不能只评估已知错误集。约 0.02 个百分点 CER（当前字符分母下约 18 次编辑）可作为候选改善的操作目标，但须在相邻 checkpoint 和独立来源测试复核，不能拿单次最低点宣称稳定提升。

独立测试按文档/模板来源隔离，训练合成风格和目标选择仅从训练侧获取。现有 val 已参与错误驱动的专项合成和部分风格采样，应视为开发验证集。新增 holdout 才能验证迭代效果能否推广；不要把现有 val 错误图加入训练后仍当独立验证。

只有当上述对照稳定、标注问题已排除，且高分辨率原图显示关键笔画在 32 高输入中消失时，再测试高度 48 或增强 CNN。届时需同步核查 CNN 高度归约、有效序列长度、CTC、全部 batch 一致性测试与 CPU 性能，避免同时改模型容量、输入尺寸和数据比例导致无法归因。
